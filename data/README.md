# 節目台帳（data/）

日本発のゲームが「どれだけ売れたか」を、**後からまとめて分析できる形**で記録していくデータ。
見せるための表ではなく、1行＝1つの事実として積むデータセット。数字はすべて出典つき。

## ファイル

| ファイル | 中身 | 1行の単位 |
|---|---|---|
| `titles.csv` | 作品の台帳（変わらない情報） | 1作品 |
| `milestones.csv` | 数字の記録（時点つき・追記だけ） | 1作品 × 1指標 × 1時点 |
| `check.js` | 形の確認（`node data/check.js`） | — |
| `index.html` | **裏の窓**（https://notes.tas9.net/data/ ）。同じフォルダの CSV をブラウザで読んで**図**にする（2026-09-27 に表から図へ作り直し）。サイトからはリンクせず、検索にも載せない（noindex）。原本は CSV で、このページは読むだけ。各図の下の「表で見る」で数字も出る | — |

CSV は UTF-8（BOM つき＝Excel でそのまま開ける）。Google スプレッドシートにも取り込める。

## titles.csv の列

| 列 | 意味 | 書き方 |
|---|---|---|
| id | 作品の識別子 | 小文字英数字とハイフン（例 `mario-kart-world`）。一度決めたら変えない |
| title_ja | 作品名 | 国内での表記 |
| developer | 開発の主体 | 複数は `／` でつなぐ |
| publisher | 発売元 | 同上 |
| origin_jp | 日本発か | `1`＝開発の主体が日本にある、`0`＝それ以外 |
| release_date | 最初の発売日 | `YYYY-MM-DD`。早期アクセスなら開始日（note に明記）。確かめられない時は空にして note に「発売日は未確認」 |
| platforms | 出ている機器 | `Switch2|PS5|PC` のように `|` 区切り |
| team_size | 開発人数 | 数字か範囲（`3-40`）。いちばん多い時期の人数。不明なら空 |
| team_size_source | 人数の出どころ | URL か資料名。人数を書くなら必ず |
| size_class | 規模 | `S`＝1〜10人／`M`＝20〜100人／`L`＝200人以上（`dev.html`「規模」章と同じ区分）。人数が不明なら空 |
| steam_appid | Steam の作品番号 | ストアの URL `store.steampowered.com/app/数字/` の数字。Steam に無ければ空 |
| ip_owner | IP（作品・キャラクターの権利）の持ち主 | 会社名。共有なら並べて書く |
| ip_country | IP の持ち主の国 | 2文字の国コード（JP／US／CN／KR／SE…）。**最終的な親会社（グループの本拠）の国**で機械的に決める（シンガポール登記の中国系運営会社は CN、ネクソン傘下の Embark は KR）。事情は note に |
| dev_country | 開発の主体の国 | **実際に作っている拠点の国**（人が働いている場所）。`origin_jp=1` なら JP。複数国にまたがれば空にして note に |
| pub_country | 販売・運営の主体の国 | ip_country と同じく最終的な親会社の国。スマホは「運営して売上を受け取る会社」 |
| country_source | 国籍の出典 URL | 会社の会社概要・有価証券報告書（EDINET）・買収の公式リリース・ストアの販売元表示など。国籍を書くなら必須 |
| release_source | 発売日の出典 URL | 公式の発売告知・ストアのページなど。無い時は note に「発売日の出典は未添付」と書く |
| note | 補足 | 早期アクセス・別エディション・機器ごとの発売日など |

## milestones.csv の列

| 列 | 意味 | 値 |
|---|---|---|
| id | 作品の id | `titles.csv` にある id だけ |
| metric | 何の数字か | `units_sold`（販売本数）／`units_shipped`（出荷本数）／`units_shipped_dl`（出荷＋DL 販売）／`players`（プレイヤー数）／`revenue`（売上額）／`reviews`（Steam のユーザーレビュー数） |
| value | 数字 | 整数・桁区切りなし（1,539万本 → `15390000`） |
| unit | 単位 | `本`／`人`／`円`／`件` |
| precision | 数字の性格 | `exact`＝その時点の値（IR の一覧など）／`at_least`＝「○万本突破」＝それ以上 |
| scope | 地域 | `world`／`japan` |
| channel | 数え方の範囲 | `all`（全部）／`package`（店頭のパッケージ中心。ファミ通はパッケージ＋DL カード＋本体同梱）／`digital`／`steam` |
| basis | 数字の出どころの性格 | `official`（会社の発表・IR）／`estimate`（第三者の推計）／`press`（報道・調査会社の集計） |
| as_of | いつ時点の値か | `YYYY-MM-DD`。IR は基準日、「突破」の発表は発表日 |
| source_name | 出典の名前 | 会社名・媒体名 |
| source_url | 出典の URL | 必ず |
| note | 補足 | 「発売初日」「初週」「Switch 2 Edition のみ」など |

## 順位表 rankings.csv（誰の作品にユーザーの興味が向いたか）

「日本は好調」を会社の決算で見るのとは別に、**ユーザーが実際に選んだ作品の国籍**を測るための表。市場ごとに「全作品を同じ方法で並べた表」をそのまま写す。

| 列 | 意味 |
|---|---|
| list_id | 表の識別子（例 `famitsu-annual-jp-2025`・`steam-best-of-2025`・`sensortower-jp-mobile-revenue-2025`） |
| list_name / market / metric | 表の名前／市場（`japan-console`・`japan-mobile`・`world-pc`・`us-console`…）／並べた物差し（`units_sold_package`・`iap_revenue_rank`・`gross_revenue_tier`…） |
| period_end | 集計期間の最終日 |
| rank | 順位（帯だけで順位が無い表は、載っている順に番号を振り note に「順不同」と書く） |
| title_id | `titles.csv` の id（無い作品は titles.csv にも足す。海外作品は `origin_jp=0`） |
| value / unit | 表に数値があればその値（無ければ空） |
| basis / source_name / source_url / note | 出典（推計の表は `estimate`） |

- 使う表（毎年同じものを使う）：**国内家庭用**＝ファミ通の年間ソフト販売本数ランキング TOP10／**国内スマホ**＝Sensor Tower の年間収益ランキング TOP10（推計）／
  **世界 PC**＝Steam「年間ベスト」トップセラーのプラチナ12本（公式・総収益の帯・順不同）。米国家庭用（Circana の年間 TOP）は出典が取れた年だけ。
- **出す数字**：各表の上位のうち、`ip_country=JP` の割合／`dev_country=JP` の割合／`pub_country=JP` の割合。3つの差が「日本は権利者か、作るだけの受託側か」を示す。
  - 例（2025年）：国内家庭用 TOP10 は日本 IP が9本。国内スマホ TOP10 は日本 IP が7本で、1位・5位・8位は中国 IP。
- 国籍の判定：IP と販売運営は「最終的な親会社の国」、開発は「作っている拠点の国」。お金と権利が最後にどこへ行くかを見るのが目的なので、地域の登記（シンガポール法人など）では決めない。
  IP が共有（例：ポケモン＝任天堂・クリーチャーズ・ゲームフリーク）、IP が許諾（例：Dune＝米国の許諾・開発ノルウェー・販売テンセント）などの事情は note に書き、判定は変えない。
- 2025年の3表を入れた時点の観測：Steam トップセラーのプラチナ12本のうち日本 IP は1本（モンスターハンターワイルズ）、新作のプラチナ12本では2本（＋ELDEN RING NIGHTREIGN）。
  国内スマホ TOP10 は日本 IP 7本・中国 IP 3本。国内家庭用 TOP10 は日本 IP 9本。
- **この3表の偏り（読む時に必ず添える）**
  - ファミ通はパッケージ中心（DL 販売を含まない）。DL 比率の高い海外作品や PC・大人向け作品が実態より下に出るので、「国内家庭用は日本 IP 9本」は**日本に有利に出た数字**。
  - Steam の年間ベストは「帯」だけで順位が無い（rank は掲載順に振った番号）。トップセラーは発売年を問わない総収益なので、長く運営されている基本無料の作品が強く出る。
    2025年分は 12月1日時点の集計を 12月30日の報道で確認したもので、Valve の最終版（2026-01-01 更新）と公式ページ本文は機械から読めず未確認。
  - 国内スマホは Sensor Tower の推計（金額は非公開・集計は 12月17日まで）で、4Gamer の掲載を写した。1位と2位は日経の報道とも一致。
  - 抜けている市場：米国家庭用（Circana）・中国（世界最大）・世界のスマホ。ここを足すと日本 IP の見え方はさらに小さくなる可能性が高い。
- **国籍の3列の裏取り（2026-09-27）**：50作品すべてに `country_source` を付けた。上場会社は EDINET の有報（本店所在地は XBRL の表紙で確認）、未上場は会社概要ページ、
  買収は公式リリース（Embracer→Warhorse、Tencent→Funcom、Nexon→Embark）、シンガポール登記の中国系運営会社は Google Play の販売元表示＋グループの本拠を報じた記事。
  **出典が付けられなかったもの**（note に「出典は未添付」と明記）：Microsoft による Activision・Bethesda・Mojang の買収（公式ページが機械で読めず）、
  任天堂の子会社エヌディーキューブの所在地、KRAFTON の本社所在地の記載、miHoYo（上海）と COGNOSPHERE の関係（報道による）。発売日の出典が無い作品は `release_source` が空。
  Steam のストア表示は米国時間なので、日本時間の発売日と1日ずれることがある（note に明記）。

## 裏の窓（index.html）の図と配色の約束

- 章（2026-09-27 夕方に本人の7点の指摘で作り直した形）：
  00 市場と人口（数字の札）／01 誰の作品が選ばれたか（国籍で塗った100%の帯。**冒頭に「この景色は日本に寄っている」の注記**＝4表のうち2表が国内・世界は PC のみ・国内家庭用はパッケージ集計）／
  02 世界のどこの会社か（IP の持ち主・開発の拠点・販売運営の**3枚の国別横棒**。タイル地図は「イメージがわかない」でやめた）／
  03 勢い（会社ごとの小さな折れ線・最初の年＝100・売上は実質に切り替え可。**札の下に「信号」**＝売上と人は直近3年の年率 ±5%、利益率は3年前との差 ±3pt で ↑→↓。
  **A〜E の成績は付けない**＝重み付けが主観になり、当たり作1本で跳ねる小さな会社を誤読させるため）／
  04 弾込め（**研究開発費÷売上高の推移**の小さな折れ線＋作りかけの残高の前年比。冒頭に「会社をまたいで金額は比べない」の注記）／
  05 労働の取り分（**給与÷（給与＋1人あたり営業利益）**＝1人が生んだ稼ぎのうち給与に回った割合。白抜き＝3〜5年前・緑＝最新の2点を線で結ぶ。散布図は「イメージがわかない」でやめた）／
  06 資本の所在（外国法人等の持株比率の横棒。注記で「これは持たれている側の数字・逆向き＝日本が海外を買う流れもある」）／
  07 節目（**日数の軸に点**。縦線＝1か月・100日・1年。塗り＝突破の発表日・白抜き＝「その日までに」。横棒はやめた）。
- 配色は「色弱でも隣り合う色が見分けられるか」を機械で検証した組み合わせだけを使う（dataviz の validate_palette.js。ライト・ダーク別に検証）。
  国の色：日本 `#4f7d12`／米国 `#1160c9`／中国 `#c2562a`／韓国 `#0a93a8`／欧州 `#6b5bd2`／その他は灰（ダークは `#6e9c3a` `#3d86e0` `#d86a2f` `#1f97aa` `#7d6fd0`）。
  増減は青（増）×橙（減）。国別の棒は日本だけ緑・他は灰（順位は長さで読む）。文字は必ず文字色で、色は印にだけ使う。2つ以上の系列には必ず凡例。
- 動かす部分は「実質の切り替え」「印に触れた時の吹き出し」だけ。アニメーションは無し。
- 作り方：同じフォルダの **`build_index.py`** が news.html の骨組み（上の行・写真・題名・署名）を写して `index.html` を生成する
  （`py D:/tas9_labo/web/notes/data/build_index.py`）。共通の見た目を変えたら作り直す。**index.html を直接編集しない**（次の生成で消える）。
  クラス名は `lg-` を頭に付ける（共通 style.css の `.box` `.hbars` `.bar` `.down` などと衝突したため）。

## 記入のルール

1. **追記だけ。上書きしない。** 累計は増え続けるので、新しい数字は新しい行にする（同じ作品でも時点が違えば別の行）。
2. **単位の違う数字を混ぜない。** 本数と人数と売上額は metric と unit で分ける。並べて足さない。
3. **定義が分からない数字は書かない。** 「販売か出荷か」「世界か国内か」が読み取れない発表は、分かるまで保留。
4. **出典は1行に1つ。** 2つの出典がある時は行を分ける（数字が違えば別の事実）。
5. **推計は推計と書く。** `basis=estimate` の行は、公式の行と別に扱えるようにする（検算のため）。
6. 書いたら `node data/check.js` で形を確かめる（列・日付・重複・id の対応）。
7. **追記は人とルーティンの両方**（2026-09-26 から）。ルーティン `notes-check` は毎月、公式の「突破」発表・IR 一覧の更新を `milestones.csv` に、
   Steam のレビュー数を `steam_update.js` で足し、`check.js` を通してから push する。評価や予想は書かない・既存の行は消さない（News と同じ条件）。

## 母集団（何を載せるか）

- **日本発**＝開発の主体が日本にある作品（発売元の国籍ではない）。大手もインディーも同じ1行。
- 国内ランキングに入った海外作品も**比較用に**載せる（`origin_jp=0`）。「国内の上位に日本発が何本入っているか」を出すため。分析で日本発だけを見る時は `origin_jp=1` で絞る。
- 年ごとに「その年に出た日本発の作品」を並べ、規模（S/M/L）で分けて「10万本・100万本に届いた割合」を見るのが目的。
- 会社が数字を出すかどうかで載る・載らないが決まると偏る。そのため**背骨は、全作品を同じ物差しで数える源**にする：
  - ファミ通の販売本数（国内・全社同じ方法・パッケージ中心）
  - Steam の推計（第三者・全作品・誤差は大きい）
  - スマホは売上額の推計（本数が無い）
  - 会社の「突破」発表・IR の一覧は**検証用の列**（正確だが、出す会社に偏る）
- 網羅型の源として入れているもの（2026-09-27 時点）：**ファミ通の年間ソフト販売本数ランキング TOP10**（国内・パッケージ＋DLカード＋本体同梱。2025年分を記録。毎年1月の記事から足す）と、
  **Steam のレビュー数**（下の節）。公式の開示分（IR の一覧・突破発表）は検証用の列。

## Steam の数字（steam_update.js）＝全作品を同じ物差しで数える背骨

- 本数の推計サービスは使えなかった（2026-09-26 確認：Gamalytic の API は有料プランの鍵が要る・SteamSpy は自動取得を遮断・SteamDB は本数を出していない）。
  代わりに **Steam が公式に返す「ユーザーレビュー数」**（全言語・全購入区分）を毎月そのまま記録する。レビュー数はどの作品も同じ方法で数えられる、偏りの無い観測値。
- 記録の形：`milestones.csv` に `metric=reviews`・`unit=件`・`channel=steam`・`basis=official`・`as_of=取得日`。note に好評・不評の内訳と appid。
- **本数への換算は分析の時に行い、台帳には書かない**：目安は「レビュー数 × 30〜40 ≒ Steam の販売本数」（レビュー1件あたりの購入者数。年・価格帯・地域で変わる）。
  台帳に公式の本数もある作品（例：パルワールドの Steam 約1,500万本・2024年2月）で倍率を検算してから使う。
- 対象は `titles.csv` の `steam_appid` がある作品。作品を足す時は appid も書く。
- 走らせ方：`node D:/tas9_labo/web/notes/data/steam_update.js`（同じ日に2回走らせても二重には足さない）。毎月はルーティン notes-check が実行する。

## 指標台帳（indicators.csv）＝景気・投資・労働の取り分・資本の所在・人口を、年ごとに並べる

作品の売れ行き（節目台帳）とは別に、**業界全体と主要企業の「体温」**を同じ物差しで毎年積むデータ。売上の伸びは為替と値上げで膨らむので、
「人数・本数」「実質」「1人あたり」「取り分」「誰の資本か」に分解して見るための材料。

| ファイル | 中身 | 1行の単位 |
|---|---|---|
| `indicator_defs.csv` | 指標の定義（id・名前・単位・定義・既定の出典） | 1指標 |
| `indicators.csv` | 数字の記録（時点つき・追記だけ） | 1指標 × 1主体 × 1時点 |

列：`indicator_id`（defs にある id だけ）／`entity`（会社の id か `japan`・`world`）／`period_end`（年度末や年末の日付。初任給は適用開始の4月1日）／
`value`（数字・桁区切りなし。円は円単位＝百万円の公表値は 000000 を付ける）／`unit`（defs と同じ）／`basis`（official／estimate／press）／`source_name`／`source_url`／`note`。

**主体（entity）の固定リスト＝母集団。** 会社の顔ぶれは毎年同じにする（途中で増やす時は「増やした年」を README に書く）。
- 大手7：`nintendo` 任天堂／`capcom` カプコン／`square-enix-hd` スクウェア・エニックスHD／`bandai-namco-hd` バンダイナムコHD／`sega-sammy-hd` セガサミーHD／`konami-group` コナミグループ／`koei-tecmo-hd` コーエーテクモHD
- モバイル3：`gungho` ガンホー／`mixi` MIXI／`colopl` コロプラ
- 中小5：`nippon-ichi` 日本一ソフトウェア／`tose` トーセ／`cave` ケイブ／`edia` エディア／`silicon-studio` シリコンスタジオ
- 初任給だけの主体：`sie` ソニー・インタラクティブエンタテインメント／`sega` セガ／`konami` コナミ／`square-enix` スクウェア・エニックス（事業会社）
- 全体：`japan`（国内）／`world`（世界）
- 選び方：ゲームが主業の上場企業から、規模の層（大手・モバイル・中小）が揃うように。ソニーGはゲーム以外が大きく有報の数字が分けられないので入れていない。

**読む時の注意**
- 持株会社（HD）の `avg_salary_parent` は本社の管理部門（数十〜数百人）だけの給与。事業会社の給与ではない（note に明記済み）。事業会社の平均給与が要る時は、その会社が有報を出していれば別の主体で持つ。
- `game_wip`（作りかけのゲームの残高）は会社ごとに会計処理が違う。カプコン＝「ゲームソフト仕掛品」、セガサミー＝エンタテインメントコンテンツ事業の仕掛品、
  バンナム＝連結の仕掛品（玩具等も含む）、コーエーテクモ＝費用処理で積まない。**会社をまたいで足さない**。同じ会社の年の推移を見る。
